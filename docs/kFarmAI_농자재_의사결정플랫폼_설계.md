# kFarmAI 농자재 의사결정 플랫폼 설계

## 1. 원칙

kFarmAI의 농자재 영역은 쇼핑몰이 아니라 작물·식물 문제 해결에 필요한 자재 종류와 공식 정보를 확인하는 의사결정 흐름이다. 사용자는 이상 증상, 재배환경, 날씨, 재배 단계, 공식 정보를 함께 확인한 뒤 지역 판매점과 제조사 공식 정보를 구분해 참고한다.

핵심 방향은 다음과 같다.

- 특정 제품 선택을 단정하지 않는다.
- 가격 중심 탐색보다 사용 목적, 재배환경, 공식 기준, 지역 확인을 우선한다.
- AI 참고 진단은 원인 후보와 확인 포인트를 정리하는 역할로 제한한다.
- 공공데이터와 공식정보는 안전한 확인 기준으로 제공한다.
- 지역 판매점 정보와 제조사 공식 정보는 성격을 분리한다.

## 2. 사용자 흐름

장기 흐름은 다음 순서로 확장한다.

```text
AI 참고 진단
→ 공공데이터 확인
→ 농업날씨
→ 재배가이드
→ 재배달력
→ 관련 농자재 종류
→ 제품DB
→ 제조사 공식 정보
→ 지역 판매점
→ 문의·상담 전 참고자료
→ 커뮤니티 후기
→ 데이터 축적
```

1차 화면에는 `data/kfarmai-agri-material-flow.json`을 통해 다음 흐름을 반영한다.

1. 문제 확인
2. 원인 후보 정리
3. 필요 자재 종류 확인
4. 공식 정보 확인
5. 지역 판매점·제조사 확인
6. 다음 관리 경로 연결

## 3. 문제와 자재 카테고리 연결

`data/agri-material-decision-map.json`은 사용자가 겪는 문제와 확인할 농자재 카테고리를 연결한다.

예시:

- 잎 말림: 관수·시설자재, 비료, 작물보호, 농업날씨
- 과습: 상토, 화분·도구, 관수·시설자재
- 생육 저하: 비료, 상토, 관수·시설자재, 재배가이드
- 병반: 작물보호, NCPMS 병해충 정보, 농약안전사용기준
- 웃자람: 화분·도구, 스마트팜, 농업날씨, 재배가이드

이 데이터는 특정 제품 안내가 아니라 확인해야 할 자재 종류와 공식 정보 경로를 보여주는 데 사용한다.

## 4. 카테고리 데이터 구조

`data/agri-input-categories.json`은 기존 카테고리 7개를 유지하면서 의사결정 필드를 추가한다.

- `decisionRole`: 이 카테고리를 확인하는 상황
- `problemLinks`: 연결되는 문제 유형
- `productGroups`: 확인할 제품군
- `checkBeforeUse`: 선택 전 체크포인트
- `publicDataLinks`: 연결할 공공정보 또는 공식 정보
- `regionUse`: 지역 판매점 정보의 사용 목적
- `manufacturerUse`: 제조사 공식 정보의 사용 목적
- `nextActions`: 다음 확인 경로
- `businessPotential`: 내부 설계용 장기 확장 방향

화면에는 `businessPotential`을 노출하지 않는다. 화면에는 “제조사 공식 정보와 지역 판매점 정보를 단계적으로 보완할 예정입니다.” 수준의 안내만 표시한다.

## 5. 카테고리별 역할

상토는 모종, 분갈이, 육묘, 배수, 보수성, 뿌리 활착과 연결한다. 확인 제품군은 수도용 상토, 원예용 상토, 육묘용 상토, 분갈이용 배양토다.

비료는 생육 저하, 잎색 변화, 착과, 뿌리 활력과 연결한다. 확인 제품군은 복합비료, 유기질비료, 액비, 미량요소, 칼슘제다.

종자는 파종, 품종 선택, 재배 시기, 지역 적응성과 연결한다. 확인 제품군은 과채류 종자, 엽채류 종자, 근채류 종자, 화훼 종자다.

작물보호는 병반, 해충 흔적, 이상 증상 확인과 연결한다. 등록 작물, 대상 병해충, 사용 시기, 희석배수, 안전사용기준 확인을 우선한다.

관수·시설자재는 과습, 건조, 배수, 하우스 관리, 자동관수와 연결한다. 점적호스, 스프링클러, PE관, 밸브, 필터, 펌프, 차광망, 하우스 필름을 확인 제품군으로 둔다.

화분·도구는 분갈이, 과습, 지지대, 가지치기, 실내 물관리와 연결한다. 화분, 받침, 배수망, 마사토, 분갈이삽, 전지가위, 지지대, 분무기를 확인 제품군으로 둔다.

스마트팜은 온습도 모니터링, 자동관수, 환기·차광, 양액, 데이터 기록과 연결한다. 센서, 제어기, 자동관수, 양액기, CCTV, 데이터 플랫폼을 확인 제품군으로 둔다.

## 6. 공공데이터와 공식정보

1차 반영은 화면·정적 데이터 구조 중심이다. 실제 API 연동이 없는 항목은 연동 완료처럼 표현하지 않고 “공식 정보 확인”, “공공정보 기반 확장 예정”, “시제품 일부 반영”으로 표시한다.

활용 후보:

- NCPMS 병해충 정보
- 농약안전사용기준
- 농사로 작목별 재배기술 정보
- 농작업 일정 정보
- 농업날씨
- 전국농약및비료판매업체표준데이터
- 스마트팜코리아 공개 정보
- 협회와 제조사 공식 공개 자료

API 키와 환경 변수 값은 Worker나 배포 환경에서만 사용하고, HTML·JSON·문서에는 넣지 않는다.

## 7. 지역 판매점과 제조사 공식정보 구분

지역 판매점은 위치 기반 확인용이다. 주소, 전화번호, 취급품목, 위도·경도 등은 지역별 확인 흐름에 활용한다.

제조사 공식 정보는 제품군, 규격, 사용 조건, 유지관리, 공식 고지 확인용이다. 본사 위치는 참고용이며 실제 공급, 설치, AS 가능 지역과 다를 수 있다.

두 정보를 같은 목록으로 합치지 않고 사용 목적을 분리해 표시한다.

## 8. 장기 데이터 전략

농자재 DB는 단순 업체 목록이 아니라 문제-작물-재배환경-자재 종류-공식 정보-지역 판매점-제조사 공식 정보-커뮤니티 참고 경험을 연결하는 구조로 확장한다.

장기적으로는 다음 데이터를 분리해 축적한다.

- 제품군 DB
- 제조사 공식 정보 DB
- 지역 판매점 DB
- 작물·문제별 자재 확인 규칙
- 공공정보 연결 인덱스
- 커뮤니티 후기와 도움 반응
- 문의·상담 전 참고자료 흐름

가격 정보는 직접적인 비교 기능이 아니라 시장 흐름, 문의량, 수요 신호 등 시장 인텔리전스 방향으로 다룬다.

## 9. 금지 표현

사용자 화면에서는 다음 표현을 쓰지 않는다.

- 최저가
- 구매하기
- 가격비교
- 장바구니
- 결제
- 전화주문
- 추천 농약
- 이 농약을 쓰세요
- 정확한 진단
- 최종 처방
- 병해충 발생 예측
- 방제 적기
- 오늘 방제하세요

대신 다음 표현을 사용한다.

- 참고 정보
- 공식 정보 확인
- 지역 판매점 확인
- 제조사 공식 정보
- 공공정보 기반 확장 예정
- AI 참고 진단
- 원인 후보
- 확인 포인트

## 10. 단계별 구현 계획

1. 화면 상단에 농자재 의사결정 흐름을 표시한다.
2. 문제와 농자재 카테고리 연결 데이터를 만든다.
3. 7개 카테고리에 의사결정 필드를 보강한다.
4. 지역 판매점과 제조사 공식 정보의 차이를 화면에 표시한다.
5. 공식 공공데이터 링크와 Worker 연동은 검증된 순서대로 연결한다.
6. 제품DB와 지역 판매점 DB는 검수 데이터 기준으로 단계적으로 확장한다.
