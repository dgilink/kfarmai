# kFarmAI 회원 탈퇴 및 계정 관리 설계

## 목적

회원 탈퇴는 인증 계정, 작성글, 댓글, 업로드 사진 등 사용자 데이터와 연결됩니다. 브라우저에서 즉시 계정을 삭제하는 방식은 관리자 권한이 필요한 키를 노출할 위험이 있으므로 사용하지 않습니다.

## 브라우저에서 관리자 키를 사용하지 않는 이유

Supabase Auth 사용자를 실제 삭제하려면 관리자 권한이 필요합니다. 이 권한은 서버에서만 안전하게 다뤄야 하며, 프론트엔드 HTML 또는 JS에 포함되면 누구나 확인할 수 있습니다.

따라서 브라우저 코드는 다음을 하지 않습니다.

- 관리자 삭제 함수 호출
- 관리자 권한 키 저장
- `.env.local` 또는 secret 값 노출
- 사용자 계정 즉시 삭제 단정 표시

## 1차 구현 범위

이번 단계는 안전한 탈퇴 요청 접수 흐름입니다.

1. 로그인된 MY 화면에 `회원 탈퇴` 버튼을 표시합니다.
2. 버튼 클릭 시 한 번 더 확인하는 모달을 표시합니다.
3. 취소, 바깥 영역 클릭, 뒤로가기, Escape 입력은 요청을 취소합니다.
4. `탈퇴 요청` 확인 시 요청 시각을 로컬에 기록합니다.
5. 사용자를 로그아웃합니다.
6. `탈퇴 요청이 접수되었습니다. 로그아웃 후 홈으로 이동합니다.` 안내를 표시합니다.

현재 단계에서는 Supabase Auth 사용자를 브라우저에서 직접 삭제하지 않습니다.

## 2차 구현 방향

실제 계정 삭제는 Cloudflare Worker 또는 Supabase Edge Function에서 처리합니다.

권장 흐름:

1. 프론트엔드가 로그인 세션으로 탈퇴 요청 API를 호출합니다.
2. 서버가 사용자 세션을 검증합니다.
3. 서버가 탈퇴 요청 테이블에 기록합니다.
4. 운영 정책에 따라 작성글, 댓글, 사진을 삭제 또는 익명화합니다.
5. 서버에서만 관리자 권한으로 Auth 사용자 삭제를 수행합니다.

## 탈퇴 요청 테이블 제안

아래 SQL은 사용자가 Supabase Dashboard에서 검토 후 직접 실행할 수 있는 선택안입니다. Codex 작업에서는 실행하지 않습니다.

```sql
create table public.account_deletion_requests (
  id uuid primary key default gen_random_uuid(),
  user_id uuid,
  email text,
  reason text,
  status text default 'requested',
  requested_at timestamptz default now(),
  processed_at timestamptz
);
```

## 작성 데이터 처리 원칙

탈퇴 처리 시 데이터는 성격별로 구분합니다.

- 삭제: 사용자 프로필, 업로드 사진, 개인 식별 가능 정보
- 익명화: 공개 질문, 댓글, 커뮤니티 반응 중 서비스 흐름 유지가 필요한 데이터
- 보존 검토: 공공정보 확인 로그처럼 개인 식별성이 낮고 통계 참고에 필요한 데이터

작성글과 댓글은 운영 정책과 개인정보 처리방침에 맞춰 삭제 또는 익명화 기준을 명확히 해야 합니다.

## 사용자 안내 문구

화면 안내:

```text
탈퇴 요청 후 로그인 세션이 종료됩니다.
작성한 질문, 댓글, 업로드 사진 등은 운영 정책에 따라 삭제 또는 익명화될 수 있습니다.
계속 진행하시겠습니까?
```

완료 안내:

```text
탈퇴 요청이 접수되었습니다. 로그아웃 후 홈으로 이동합니다.
```

## 향후 반영 필요

- 개인정보 처리방침에 탈퇴 요청 처리 기간과 데이터 처리 방식을 명시합니다.
- 이용약관에 작성글, 댓글, 업로드 사진의 삭제 또는 익명화 기준을 반영합니다.
- 서버 API 또는 Edge Function 구현 후 요청 접수 상태를 조회할 수 있게 확장합니다.
