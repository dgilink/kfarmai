# kFarmAI 공공데이터 매칭 1장 보고서 설계

## 1. 보고서의 목적

AI 참고 진단 결과를 공공데이터 출처와 비교해, 사용자가 확인해야 할 핵심 내용을 1장 카드 형태로 정리한다.

이 보고서는 다음 목적을 가진다.

- 사용자가 AI 진단 결과를 다시 확인할 수 있게 한다.
- 공공데이터 출처 기준으로 어떤 항목을 확인했는지 보여준다.
- 최종 판단이 아니라 참고 결과임을 명확히 한다.
- 마이페이지에 저장해 나중에 다시 볼 수 있게 한다.
- 필요 시 관계기관 상담으로 이어지게 한다.

금지 방향:

- 연구논문처럼 길게 작성
- 병명 확정
- 농약 추천
- 처방
- 방제 지시
- 불필요하게 긴 설명

## 2. 보고서 표현 원칙

사용할 표현:

- 공공데이터 매칭 결과
- 출처 기준 확인 항목
- 확인한 점
- 관련 항목 있음
- 추가 검증 권장
- 관계기관 확인 권장
- 참고자료

피할 표현:

- 정확한 진단
- 확정 진단
- 최종 처방
- AI 진단이 맞습니다
- 이 병입니다
- 이 농약을 쓰세요
- 오늘 방제하세요
- 방제 적기

핵심 문장:

```text
kFarmAI는 AI 진단 후보를 공공데이터 출처와 연결해, 확인한 항목과 추가 검증 경로를 정리합니다.
```

## 3. 1장 보고서 최종 화면 구조

보고서는 아래 순서로 구성한다.

1. 보고서 헤더
   - 제목: 공공데이터 매칭 보고서
   - 날짜
   - 작물명
   - 증상명
   - 지역/재배유형이 있으면 작게 표시

2. AI 참고 진단 요약
   - 원인 후보 2~4개
   - 짧은 chip 형태
   - 예: 해충 가능성 / 바이러스성 증상 / 고온·건조 스트레스

3. 공공데이터 매칭 결과
   - 가장 중요한 핵심 요약 1~2문장
   - 예: AI 후보 중 해충·바이러스·환경 스트레스 항목은 공공데이터 출처와 함께 확인할 수 있습니다.

4. 출처별 확인한 점
   - NCPMS
   - 농약안전정보시스템
   - 농업날씨
   - 재배가이드 또는 농사로
   - 각 출처마다 1줄만 표시

5. 추가 검증 안내
   - 관계기관 확인 권장
   - 사진, 발생시기, 지역, 재배환경을 함께 확인하라는 안내

6. 주의문구
   - 참고자료이며 최종 진단이 아님
   - 농약 사용 전 제품 라벨과 안전사용기준 확인

## 4. 1장 보고서 카드 레이아웃

모바일 카드형 레이아웃:

```text
[공공데이터 매칭 보고서]
고추 · 잎말림
2026.07.07

AI 참고 진단 후보:
[해충 가능성] [바이러스성 증상] [고온·건조]

공공데이터 매칭 결과:
관련 공공데이터 출처에서 병해충, 안전사용기준, 날씨 조건을 함께 확인할 수 있습니다.

출처별 확인한 점:
- NCPMS: 병해충·발생환경 확인
- 농약안전정보: 등록작물·안전사용기준 확인
- 농업날씨: 고온·건조·강수 확인
- 재배가이드: 생육단계·관리포인트 확인

추가 검증:
증상이 계속되거나 피해가 확산되면 관계기관 또는 전문가 상담을 권장합니다.

주의:
이 보고서는 참고자료입니다. 최종 판단은 공식자료와 전문가 확인이 필요합니다.
```

색상:

- kFarmAI green

아이콘:

## 6. 출처별 확인 결과 문구 템플릿

출처별 문구는 길게 쓰지 않는다.

| 출처 | 확인 결과 문구 |
|---|---|
| NCPMS | 병해충·발생환경 확인 |
| 농약안전정보시스템 | 등록작물·안전사용기준 확인 |
| 농업날씨 | 기온·강수·습도 확인 |
| 농사로 | 작목별 재배기술 확인 |
| 재배가이드 | 생육단계·관리포인트 확인 |
| 지역기관 | 사진·발생환경 상담 권장 |

각 출처는 1줄로 정리한다.

## 7. 매칭 상태 문구

보고서 상단에 표시할 상태 문구:

1. 공공데이터 관련 항목 매칭됨
2. 공공데이터 기준 확인 항목 있음
3. 추가 검증 권장
4. 관계기관 확인 권장

사용 예:

- 고추 잎말림 → 공공데이터 관련 항목 매칭됨
- 없는 조합 → 추가 검증 권장

주의:

- “정확”, “확정”, “일치함” 같은 강한 표현은 피한다.
- “관련 항목 매칭”, “확인 항목 있음” 정도가 적절하다.

## 9. 마이페이지 저장 구조

마이페이지에는 “공공데이터 매칭 보고서” 목록을 둔다.

목록 카드 예:

```text
고추 · 잎말림
공공데이터 관련 항목 매칭됨
2026.07.07
[보기]
```

상세:

- 1장 보고서 카드 표시

기능:

- 보고서 보기
- 삭제
- 나중에 PDF 저장/공유 확장 가능

초기 구현:

- Supabase 저장 전에는 localStorage 임시 저장 가능
- 로그인 사용자 기준으로 Supabase 저장하는 구조는 다음 단계

장기 테이블 후보:

`diagnosis_reports`

필드:

- id
- user_id
- crop
- symptom
- region
- cultivation_type
- ai_candidates jsonb
- match_status text
- match_summary text
- source_checks jsonb
- next_step text
- caution text
- image_url text
- created_at timestamptz
