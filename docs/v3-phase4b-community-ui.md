# V3 Phase 4B 커뮤니티 UI 계약

## 홈과 탐색

- 홈의 우선순위는 검색과 질문하기, 4개 목적 분류, 실제 커뮤니티 Feed, 태그 탐색 순이다.
- AI 참고 진단과 오늘의 농업정보는 Feed 다음의 보조 영역이다.
- 사용자에게 식집사·농업인 같은 유형 선택을 요구하지 않는다.
- 홈 핵심영역에는 공모전, MVP, 데모, 시제품, 준비중 CTA를 노출하지 않는다.

## 4분류와 legacy

- 새 글과 기본 탐색은 `question-help`, `cultivation-knowhow`, `showcase-daily`, `agri-field-info`만 사용한다.
- 과거 8채널 UUID는 데이터 추적과 기존 URL 호환을 위해 유지한다.
- `plant-share` 글은 삭제하지 않고 `category_id = null`인 ARCHIVE 상태로 보존한다. 기본 Feed, 검색, 새 글 선택지에서는 제외하며 기존 직접 URL에서는 읽기만 허용한다.
- 거래 등록, 결제, 배송, 정산 기능은 제공하지 않는다.

## Feed와 반응 수

- 댓글 수, 같은 증상 수, 도움됐어요 수와 로그인 사용자의 반응·저장 상태는 `community_feed_metrics(uuid[])` 한 번의 batch RPC로 조회한다.
- 최대 100개 게시글 ID를 한 요청으로 처리하며 게시글마다 별도 count 요청을 만들지 않는다.
- 비밀댓글과 삭제 표시 댓글은 Feed 댓글 수에 포함하지 않는다.
- RPC 오류 시 임의 숫자를 만들지 않고 해당 지표를 표시하지 않는다.

## 차단과 신고

- 로그인 사용자가 차단한 작성자의 게시글은 홈 Feed, 분류 목록, 검색 결과에서 숨긴다.
- 차단한 작성자의 댓글은 게시글 상세에서 숨기고 반응할 수 없게 한다.
- MY의 `차단한 사용자 관리`에서 차단 목록을 확인하고 해제할 수 있다.
- 신고는 게시글·댓글의 DB 신고 계약을 사용한다. 성공, 중복, 실패를 구분하며 다른 사용자의 신고 내역은 표시하지 않는다.

## 작성과 AI draft

- 작성자는 먼저 글 목적 4분류를 고르고 작물, 증상·주제, 지역, 재배방식, 최대 8개 태그를 선택적으로 입력한다.
- 질문·문제해결에서는 사진 첨부 영역을 강조한다.
- AI 참고 진단의 `이 내용으로 질문하기`는 작물, 증상, 태그와 확인 내용을 로컬 draft로 넘긴다.
- draft는 자동 공개되지 않으며 사용자가 작성 화면에서 확인하고 게시해야 한다.

## 검색과 과거 검색 경로

- 홈 검색은 현재 Supabase 게시글의 제목, 본문, `crop_tag`, `region_tag`, `tags`를 중심으로 조회한다.
- `search_result.html`의 과거 Render 검색 API는 V3 홈의 기본 검색 경로가 아니다. 이 파일은 호환성 검토 후 REMOVE-LATER 후보로 관리하며 Phase 4B에서는 삭제하지 않는다.

## 적용과 rollback

- Phase 4B migration은 기존 게시글·댓글·사진을 삭제하지 않는다.
- rollback SQL은 batch RPC를 제거하고 archive 매핑의 `category_id`를 복원한다.
- Production 적용 전에는 기존 `plant-share` 직접 URL 조회와 기본 Feed 미노출을 함께 확인한다.
