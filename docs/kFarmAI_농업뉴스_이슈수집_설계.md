# kFarmAI 농업뉴스 이슈수집 설계

## 1. 목적

이 문서는 농업정보 탭의 "오늘의 농업 이슈"를 매일 업데이트할 수 있는 안전한 수집·검수·게시 구조를 설계한다.

kFarmAI의 농업뉴스 영역은 기사 본문을 복사해 보여주는 뉴스 서비스가 아니다. 사용자가 오늘 농업계에서 많이 다뤄지는 이슈를 빠르게 확인하고, 자세한 내용은 각 언론사 원문으로 이동해 확인하도록 돕는 링크 큐레이션 구조다.

목표는 다음과 같다.

- 농업정보 탭에서 오늘의 농업 이슈를 매일 갱신한다.
- 기사 본문 복사 없이 제목, 출처, 날짜, 원문 링크 중심으로 제공한다.
- kFarmAI 자체 카테고리와 태그로 사용자가 빠르게 맥락을 파악하게 한다.
- 기사 이미지, 언론사 썸네일, 언론사 로고를 저장하거나 재사용하지 않는다.
- 언론사 약관, robots.txt, 저작권 리스크를 낮춘다.

## 2. 권장 수집 주기

초기에는 수집 빈도를 낮게 잡고, 운영 안정성과 검수 품질을 먼저 확인한다.

### 초기

```text
하루 1회 오전 8시
```

이유:

- 전날 저녁부터 당일 오전까지 나온 주요 농업 이슈를 한 번에 정리할 수 있다.
- 중복 기사와 품질 낮은 항목을 검수하기 쉽다.
- 자동화 초기의 법적·운영 리스크를 낮출 수 있다.

### 안정화 후

```text
하루 2회 오전 7시 30분, 오후 5시 30분
```

이유:

- 오전에는 당일 주요 이슈를 제공한다.
- 오후에는 정책, 시세, 기상, 지역농업 관련 후속 보도를 보완할 수 있다.

### 트래픽 증가 후

```text
하루 3회까지 검토
```

단, 너무 잦은 수집은 중복, 품질 저하, 언론사 약관·robots.txt 리스크를 키울 수 있으므로 신뢰 출처와 검수 체계가 먼저 필요하다.

### 허용

- 발행일
- 원문 링크
- 카테고리
- 태그
- kFarmAI 자체 이슈 설명

### 금지

- 기사 본문 저장
- 기사 본문 요약 재게시
- 기사 이미지 저장
- 언론사 썸네일 저장
- 언론사 로고 무단 사용
- 유료기사 우회
- 로그인 기사 우회
- robots.txt 무시
- 언론사 페이지 구조를 우회하는 대량 스크래핑

## 4. 데이터 구조 제안

### 파일 기반 MVP

초기에는 현재 농업정보 탭 구조에 맞춰 JSON 파일로 운영한다.

```text
data/agri-info/agri-news-issues.json
```

필드:

```json
{
  "id": "news-20260707-001",
  "issueTitle": "장마·고온기 농작물 관리 이슈",
  "title": "기사 원문 제목",
  "sourceName": "언론사명",
  "sourceUrl": "https://example.com/news/...",
  "publishedAt": "2026-07-07",
  "category": "기상·재배",
  "tags": ["장마", "고온", "농작물관리"],
  "summaryByKfarmai": "장마와 고온기 작물 관리 관련 보도가 늘고 있습니다. 원문에서 지역별 상세 내용을 확인하세요.",
  "status": "pending",
  "collectedAt": "2026-07-07T08:00:00+09:00",
  "reviewedAt": "",
  "sourceType": "news"
}
```

### status 값

- `pending`: 후보 수집 완료, 관리자 검수 전
- `active`: 검수 완료, 화면 표시 가능
- `hidden`: 이전에 표시했지만 현재 숨김
- `rejected`: 출처 불명확, 중복, 저작권·약관 리스크 등으로 제외

## 5. 자동 수집 흐름

### 1단계: 수동 입력

운영자가 직접 기사 제목, 언론사명, 발행일, 원문 링크를 확인해 JSON에 입력한다.

장점:

- 법적 리스크가 낮다.
- 품질 관리가 쉽다.
- 서비스 초기 데이터 톤을 맞추기 좋다.

단점:

- 매일 수동 운영 부담이 있다.

### 2단계: Worker Scheduled Cron 후보 수집

자동화는 바로 화면 노출이 아니라 후보 수집까지만 담당한다.

흐름:

```text
Worker Scheduled Cron
→ RSS/공개 링크 후보 수집
→ 제목/URL/언론사/날짜만 저장
→ 중복 제거
→ 카테고리 자동 분류
→ status=pending
→ 관리자 검수
→ active 전환
```

중요:

- 기사 본문은 수집하지 않는다.
- 기사 이미지는 수집하지 않는다.
- 원문 페이지를 우회하거나 로그인/유료기사에 접근하지 않는다.
- robots.txt와 제공처 정책을 확인한다.

### 3단계: 신뢰 출처 일부 자동 active

검수 운영이 안정화된 후 일부 신뢰 출처만 자동 active를 검토한다.

조건:

- RSS 또는 공식 공개 API를 제공한다.
- 제목, 링크, 발행일 사용이 허용된다.
- 본문과 이미지를 수집하지 않아도 목록 품질이 충분하다.
- 일정 기간 동안 rejected 비율이 낮다.
- 관리자 사후 숨김/수정 기능이 준비되어 있다.

## 6. 자동 수집 주체 후보

### Cloudflare Workers Scheduled Trigger

장점:

- 현재 Worker 구조가 있으면 자연스럽게 확장할 수 있다.
- Cron 실행이 가능하다.
- KV, D1, R2와 연동할 수 있다.
- 외부 API 프록시와 같은 계층에서 운영 상태를 관리하기 좋다.

단점:

- Supabase 저장 시 service key 또는 안전한 서버 측 인증 설계가 필요하다.
- 오류 모니터링과 재시도 구조를 따로 설계해야 한다.

### Supabase Edge Function

장점:

- Supabase DB와 가깝다.
- 테이블 저장이 편하다.
- RLS와 server-side 권한 흐름을 같이 설계하기 좋다.

단점:

- Cron 스케줄링 구성이 별도로 필요할 수 있다.
- Worker와 기능이 중복될 수 있다.

### GitHub Actions

장점:

- 파일 JSON 갱신 자동화가 가능하다.
- 정적 파일 기반 MVP와 잘 맞는다.
- PR 생성 방식으로 사람이 검수하기 좋다.

단점:

- 자동 커밋은 충돌 가능성이 있다.
- secret 관리가 필요하다.
- 잘못 구성하면 원치 않는 파일까지 커밋될 수 있다.
- 운영 데이터 갱신과 코드 배포가 섞일 수 있다.

### 추천

초기에는 아래 중 하나를 권장한다.

```text
수동 JSON 관리
또는
Worker + Supabase table에 pending 후보 저장
```

완전 자동 커밋은 나중에 검토한다. 특히 `git add .` 또는 자동 커밋으로 secret 후보 파일이 포함되는 구조는 금지한다.

## 7. 저장 위치 설계

### 초기

```text
data/agri-info/agri-news-issues.json
```

사용 방식:

- 운영자가 직접 검수한 active 항목을 관리한다.
- pending 항목은 화면에 표시하지 않는다.
- 정적 배포와 잘 맞는다.

### 중기

```text
Supabase table: agri_news_issues
```

테이블 후보:

```text
- id
- issue_title
- title
- source_name
- source_url
- published_at
- category
- tags
- summary_by_kfarmai
- status
- collected_at
- reviewed_at
- source_type
- created_at
```

추가 검토 필드:

```text
- normalized_title
- canonical_url
- reviewer_id
- reject_reason
- hidden_reason
- duplicate_group_id
```

## 8. 중복 제거 기준

중복 제거는 화면 품질과 운영 편의를 위해 필요하다.

기준:

- `sourceUrl` 기준 1차 중복 제거
- URL query string 정리 후 canonical URL 비교
- title 정규화 후 유사 중복 제거
- 같은 기사/보도자료 재배포는 하나만 노출
- 같은 이슈를 여러 언론이 다룬 경우 `issueTitle`로 묶는 구조 검토

정규화 예:

```text
공백 제거
특수문자 일부 제거
따옴표/괄호 정리
언론사별 추적 파라미터 제거
```

같은 이슈 여러 언론 처리:

```text
issueTitle: 장마·고온기 농작물 관리 이슈
items:
  - 농민신문 기사
  - 한국농어민신문 기사
  - 지역 언론 기사
```

초기 MVP에서는 묶음 구조까지 만들지 않고, active 목록에서 같은 이슈가 과도하게 반복되지 않도록 관리자 검수로 조정한다.

## 9. 카테고리 분류 기준

농업정보 탭과 `agri-news.html`에서 사용할 카테고리는 아래 기준을 따른다.

- 기상·재배
- 가격·유통
- 정책·지원사업
- 스마트농업
- 병해충·작물보호
- 농자재·비료
- 축산
- 수출·시장
- 지역농업
- 기타

자동 분류는 제목과 태그만 보고 초안을 만든다. 본문을 읽고 분류하지 않는다.

예시:

```text
장마, 폭염, 냉해, 가뭄 → 기상·재배
도매가격, 출하량, 수급, 유통 → 가격·유통
지원사업, 보조금, 정책, 공모 → 정책·지원사업
스마트팜, AI, 로봇, 드론, 센서 → 스마트농업
병해충, 농약안전, 방제 기준 → 병해충·작물보호
비료, 상토, 농자재, 토양 → 농자재·비료
한우, 낙농, 양돈, 가금 → 축산
수출, 해외시장, 검역 → 수출·시장
시군, 농업기술센터, 지역 행사 → 지역농업
```

## 10. 화면 표시 방식

### 농업정보 탭

농업정보 탭에는 최신 active 항목 3~5개만 compact하게 표시한다.

표시 항목:

- 카테고리 배지
- `issueTitle`
- `sourceName`
- `publishedAt`
- 원문 보기
- 더보기

표시하지 않는 것:

- 기사 본문
- 기사 전문 요약
- 기사 이미지
- 언론사 로고

### agri-news.html

농업 이슈 전체 목록 페이지에서는 active 항목 전체를 보여준다.

구성:

- 상단 설명
- 카테고리 필터
- 날짜순 정렬
- 뉴스 이슈 목록
- 원문 보기
- 저작권 안내

목록 항목:

- 카테고리 배지
- issueTitle
- title
- sourceName
- publishedAt
- tags
- 원문 보기 버튼

## 11. 저작권 안내 문구

화면과 문서에 아래 문구를 사용한다.

```text
kFarmAI는 기사 본문을 저장하거나 재게시하지 않습니다. 뉴스 제목, 출처, 날짜, 원문 링크와 자체 이슈 분류만 제공합니다. 기사 내용은 각 언론사 원문에서 확인하세요.
```

추가 안내:

```text
원문 링크는 각 언론사 사이트로 이동합니다.
```

```text
기사 이미지와 언론사 로고는 저장하거나 재사용하지 않습니다.
```

## 12. 관리자 검수 기준

`active` 전환 조건:

- sourceUrl이 정확하다.
- sourceName이 정확하다.
- publishedAt이 있다.
- 기사 본문 복사가 없다.
- 기사 이미지 저장이 없다.
- 언론사 로고 무단 사용이 없다.
- 유료/로그인 우회가 아니다.
- robots.txt 또는 제공처 정책을 의도적으로 무시하지 않았다.
- kFarmAI 자체 설명이 기사 본문을 대체하지 않는다.
- category와 tags가 화면 분류에 맞다.

`rejected` 처리 기준:

- 출처가 불명확하다.
- 원문 링크가 깨졌다.
- 본문 복사 또는 과도한 요약 위험이 있다.
- 로그인/유료기사 우회 가능성이 있다.
- 광고성·홍보성 기사로 보인다.
- 동일 기사 중복이다.
- 농약 추천, 최종 처방, 구매 유도처럼 kFarmAI 안전 원칙과 맞지 않는다.

## 13. 향후 관리자 페이지 연동

관리자 페이지가 생기면 아래 기능을 연결한다.

- pending 목록 보기
- active 전환
- hidden 처리
- rejected 처리
- 카테고리 수정
- issueTitle 수정
- tags 수정
- 중복 병합
- 원문 링크 확인
- 수집 실패 로그 확인

관리자 화면의 기본 흐름:

```text
pending 후보 목록
→ 원문 링크 확인
→ 제목/출처/날짜 확인
→ kFarmAI 분류와 태그 수정
→ active 전환 또는 rejected 처리
```

## 14. 구현 단계 제안

### 1단계: 수동 JSON + agri-news.html

- `data/agri-info/agri-news-issues.json` 유지
- active 항목만 화면 표시
- pending은 화면 미노출
- 운영자가 직접 검수 후 active 전환

### 2단계: Worker가 후보만 수집해 pending 저장

- Worker Scheduled Trigger 사용
- RSS 또는 공개 링크 후보에서 제목/URL/출처/날짜만 수집
- 중복 제거
- status=pending 저장
- 관리자 검수 전 화면 미노출

### 3단계: 관리자 페이지에서 검수/active 전환

- pending 후보 목록 제공
- 원문 보기 버튼
- 카테고리/태그 수정
- active/hidden/rejected 처리

### 4단계: 신뢰 출처 자동 active 일부 허용

- 검수 이력이 안정적인 출처만 제한적으로 자동 active
- 자동 active 후에도 관리자 숨김 가능
- 오류 발생 시 feature flag 또는 status hidden으로 즉시 차단

## 15. 운영상 주의사항

- 기사 원문은 저장하지 않는다.
- 기사 이미지는 저장하지 않는다.
- 언론사 로고를 무단으로 쓰지 않는다.
- 기사 본문을 요약해 대체 콘텐츠처럼 보이게 하지 않는다.
- `summaryByKfarmai`는 기사 요약이 아니라 kFarmAI 자체 이슈 설명이어야 한다.
- 원문 링크가 깨졌거나 출처가 불명확하면 active로 전환하지 않는다.
- 자동화는 검수 부담을 줄이는 도구이지, 무검수 게시를 전제로 하지 않는다.

### 16.1 오늘의 농업 이슈 수동 JSON/화면 구현 지시어

```text
C:\Users\user\PERSONAL\dev\kfarmai-web 폴더에서 작업한다.

먼저 AGENTS.md를 읽고 지침을 따른다.
```

## 17. 결론

오늘의 농업 이슈는 사용자가 농업정보 탭에서 매일 확인할 이유를 만들어주는 콘텐츠다. 다만 뉴스는 저작권과 언론사 약관 리스크가 있으므로, 본문·이미지·썸네일을 저장하지 않고 제목, 출처, 날짜, 원문 링크, kFarmAI 자체 분류만 제공하는 링크 큐레이션 구조가 안전하다.

초기에는 수동 JSON 운영으로 품질을 맞추고, 이후 Worker 또는 Supabase Edge Function으로 후보만 pending 저장한 뒤 관리자 검수를 거쳐 active 전환하는 단계적 구조를 권장한다.
