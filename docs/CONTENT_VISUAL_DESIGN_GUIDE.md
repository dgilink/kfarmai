# DGI 콘텐츠 비주얼 디자인 제작지침 v1.0

- 적용 범위: DGI PICK, kFarmAI, Blogger 및 이후 추가되는 콘텐츠 채널
- 기준일: 2026-10-29
- 목적: 사진·대표 이미지·인포그래픽의 품질을 통일하되, 고정 템플릿의 반복을 피하고 주제별 편집 디자인을 강화한다.

## 1. 최우선 원칙

1. 콘텐츠의 핵심을 한눈에 이해하게 한다. 장식보다 정보 위계를 우선한다.
2. 사진을 쓸 수 있으면 권리 확인된 실사·공식 사진을 우선한다.
3. 적절한 실사가 없으면 실제와 같은 질감의 고품질 이미지를 제작하되 실제 현장 사진으로 오인시키지 않는다.
4. 모든 이미지를 인포그래픽으로 만들지 않는다. 사진·편집 그래픽·정보 그래픽의 역할을 구분한다.
5. 모바일 360px·390px 화면에서 제목과 핵심 수치가 즉시 읽혀야 한다.
6. 플랫폼별 독자와 화면에 맞게 변형하고 동일 결과물을 기계적으로 복제하지 않는다.

## 2. 벤치마킹 방향

다음 사이트의 원리를 참고하되 구성이나 결과물을 그대로 복제하지 않는다.

- 29CM: 사진 중심의 에디토리얼 구성과 제품·주제의 분위기 전달
- Toss: 큰 타이포그래피, 명확한 위계, 제한된 색상과 충분한 대비
- Reuters Graphics: 사실·수치·과정을 빠르게 이해시키는 설명형 시각화
- The Pudding: 글과 시각 자료가 함께 흐르는 스토리텔링
- Material Design: 접근 가능한 대비와 콘텐츠에 반응하는 동적 색상 체계

## 3. 이미지 패키지 구성

기본 패키지는 아래 세 역할로 구성하되 글의 성격에 따라 수를 조정한다.

| 역할 | 기본 형식 | 목적 |
|---|---|---|
| 대표 이미지 | 실사 또는 사진형 에디토리얼 비주얼 | 주제와 분위기를 즉시 전달 |
| 핵심 설명 이미지 | 인포그래픽·도표·비교·과정 | 핵심 정보 하나를 빠르게 이해 |
| 맥락·마무리 이미지 | 실사, 상황 이미지, 요약 그래픽 | 독자의 다음 행동이나 결론 강화 |

- 세 장 모두 같은 카드형 인포그래픽으로 만들지 않는다.
- 정보가 단순하면 인포그래픽을 억지로 추가하지 않는다.
- 정보가 많으면 글자를 줄이지 말고 이미지를 두 장 이상으로 나눈다.

## 4. 사진 및 이미지 소스 우선순위

1. 사용자가 제공하고 사용 권한이 확인된 사진
2. 라이선스와 출처가 확인된 공식·공공·스톡 사진
3. 직접 제작한 사진형 이미지 또는 편집 그래픽
4. 순수 인포그래픽·도표

공통 제한:

- 기사 사진이나 제3자 작품을 복사·재현하지 않는다.
- 인물·장소·작물 상태를 실제 취재나 진단 결과처럼 표현하지 않는다.
- AI로 만든 사진형 이미지는 실제 현장 기록으로 설명하지 않는다.
- 로고·표지판·제품명·공식 문서 화면을 임의로 만들어 넣지 않는다.

## 5. 색상 체계

### 5.1 동적 팔레트

- 네이비·그린·아이보리처럼 전 채널에 고정된 팔레트를 사용하지 않는다.
- 주제, 대표 사진, 계절, 감정, 정보 성격에서 색을 선택한다.
- 한 이미지에는 `주조색 1 + 강조색 1 + 중립색`을 기본으로 한다.
- 강조색은 핵심 수치·상태·행동 한두 곳에만 사용한다.
- 텍스트와 배경의 대비는 일반 텍스트 WCAG AA 4.5:1 이상을 목표로 한다.
- 사진 위 텍스트는 실제 사진의 명암을 확인한 뒤 단색 오버레이나 그라데이션 마스크를 최소한으로 사용한다.

### 5.2 피해야 할 색 사용

- 모든 결과물의 네이비·그린·아이보리 고정 조합
- 전체 화면을 덮는 탁한 파스텔 또는 회색빛 베이지
- 의미 없이 많은 색을 섞은 무지개 팔레트
- 글자 자체의 과도한 그라데이션·네온·금속 질감
- 브랜드와 무관한 색을 장식용으로 반복 사용

## 6. 레이아웃과 안전영역

- 기본 캔버스: 1200×675px, 16:9. 플랫폼 요구가 있으면 1:1 또는 4:5 파생본을 만든다.
- 바깥 안전영역: 긴 변 기준 3~5%, 1200px 기준 36~60px.
- 주요 사진·도형은 캔버스의 약 85~92%를 활용해 과도한 빈 공간을 만들지 않는다.
- 제목·핵심 수치·주요 피사체만 안전영역 안에 둔다. 배경과 장식 요소는 가장자리까지 확장할 수 있다.
- 모바일 본문에서는 이미지가 콘텐츠 폭을 자연스럽게 채우도록 하고, 불필요한 회색 카드나 이중 여백을 두지 않는다.
- 360px, 390px, 768px, 1280px 화면에서 크롭·줄바꿈·가독성을 확인한다.

## 7. 타이포그래피

1200×675px 기준 권장값:

| 요소 | 권장 크기 | 규칙 |
|---|---:|---|
| 대표 제목 | 56~84px | 1~2줄, 굵게, 짧게 |
| 핵심 수치 | 72~110px | 이미지에서 가장 먼저 보이게 |
| 본문 핵심 설명 | 34~48px | 2~4개 항목 이내 |
| 보조 문구 | 28~34px | 꼭 필요한 경우만 |
| 출처·각주 | 24~28px | 이미지 안에 최소화하고 본문 출처 병행 |

- 1200×675px 이미지에서 24px 미만 글자는 원칙적으로 사용하지 않는다.
- 작은 글씨로 정보를 우겨 넣지 않는다. 내용이 많으면 이미지를 분할한다.
- 한글은 이미지 생성 모델에 맡기지 않고 검증 가능한 폰트로 후처리한다.
- 제목·수치·단위·날짜·띄어쓰기를 원문과 대조한다.
- 한 이미지에 폰트 패밀리는 최대 두 개, 굵기는 세 단계 이내로 제한한다.

## 8. 형태와 구성

- 실사형 대표 이미지는 피사체가 명확하고 배경이 과하게 복잡하지 않게 한다.
- 인포그래픽은 한 장에 질문 하나, 결론 하나를 담는다.
- 도형은 정보의 그룹·비교·순서를 설명할 때만 사용한다.
- 카드와 둥근 사각형을 반복하는 자동 생성형 구성을 피한다.
- 아이콘은 같은 세트와 선 굵기를 사용하며 장식용 남발을 피한다.
- 브랜드 표시는 작고 절제되게 두며, 콘텐츠보다 먼저 보이지 않게 한다.

## 9. 절대 금지 규칙

- 이미지 왼쪽의 장식용 세로 색띠
- 인포그래픽 뒤의 불필요한 회색 카드 배경
- 같은 둥근 카드 템플릿을 모든 이미지에 반복
- 도형에 비해 지나치게 작은 글자
- 넓은 여백 때문에 실제 정보 영역이 작아지는 구성
- 네이비·그린·아이보리 고정 팔레트 강제
- 세 장 모두 같은 형식의 인포그래픽
- 사실과 다른 숫자·날짜·제품·표지판·지도
- 원본을 확인하지 않은 자동 번역 문구와 깨진 한글
- 장식용 3D 아이콘, 과도한 글로우·그림자·유리 효과

## 10. 플랫폼별 적용

### 10.1 DGI PICK

- 대표 이미지는 주제를 설명하는 실사 또는 사진형 에디토리얼 비주얼을 우선한다.
- 정책·생활 정보는 핵심 변화, 대상, 금액 또는 일정 중 하나를 중심으로 설명한다.
- 본문에 같은 대표 이미지를 반복 삽입하지 않는다.
- 이미지마다 대체 텍스트, 출처, 권리 상태를 기록한다.
- 모바일 본문 폭을 채우며 회색 바깥 카드와 과도한 좌우 여백을 사용하지 않는다.

### 10.2 kFarmAI

- 국내 농업·작물·현장 맥락이 자연스럽게 보이는 실사를 우선한다.
- 작물 증상 이미지는 실제 진단이나 처방으로 단정하지 않고 `관찰 예시`, `원인 후보`, `확인 포인트`로 표현한다.
- 농약·비료·종자 라벨, 희석배수, 안전사용기준은 공식 자료와 일치할 때만 시각화한다.
- 데이터 비교나 절차 설명에는 인포그래픽을 사용하고, 단순 분위기 전달에는 사진을 사용한다.
- 모바일 농가 사용 환경을 고려해 핵심 버튼·수치·작물명이 작은 화면에서도 즉시 읽히게 한다.

### 10.3 Blogger

- 글로벌 독자를 위한 영어 제목과 시각 문맥을 기본으로 한다.
- 한국 고유 요소는 사진이나 짧은 영문 설명으로 맥락을 제공한다.
- 1200×675px 대표 이미지를 기본으로 하고 반응형 본문에서 원본 비율을 유지한다.
- 불필요한 DGI PICK 로고를 강제하지 않는다. 소유·제작한 이미지에만 작은 표시를 허용한다.
- 이미지 파일명, 대체 텍스트, 캡션은 영문 검색 의도에 맞추되 키워드를 반복하지 않는다.

## 11. 제작 절차

1. 글의 독자, 목적, 핵심 메시지 한 문장을 확정한다.
2. 각 이미지의 역할을 `대표/설명/맥락` 중 하나로 지정한다.
3. 사용 가능한 실사와 권리 증빙을 먼저 확인한다.
4. 주제나 대표 사진에서 동적 팔레트를 정한다.
5. 1200×675px 초안을 만들고 실제 모바일 축소 크기로 검토한다.
6. 한글·숫자·날짜는 결정론적 후처리로 올리고 원문과 대조한다.
7. 대체 텍스트, 출처, 라이선스, 생성 여부를 기록한다.
8. 모바일·PC 페이지에 삽입한 최종 상태를 확인한 뒤 승인한다.

## 12. 발행 전 품질 게이트

아래 항목이 하나라도 실패하면 제작 완료로 처리하지 않는다.

- [ ] 대표 이미지가 주제를 3초 안에 전달한다.
- [ ] 이미지 세 장이 모두 같은 인포그래픽 템플릿이 아니다.
- [ ] 왼쪽 장식용 세로 색띠가 없다.
- [ ] 불필요한 회색 카드 배경이 없다.
- [ ] 360px·390px 화면에서 제목, 핵심 수치, 단위가 읽힌다.
- [ ] 1200×675px 기준 24px 미만 글자가 없다.
- [ ] 바깥 여백이 3~5% 범위를 크게 벗어나지 않는다.
- [ ] 팔레트가 주제에 맞고 고정 네이비·그린·아이보리 조합에 묶이지 않는다.
- [ ] 사실·날짜·수치·한글·영문 철자를 원문과 대조했다.
- [ ] 사진·아이콘·폰트의 사용 권리와 출처를 확인했다.
- [ ] 실제 사진과 생성 이미지를 오해하게 설명하지 않는다.
- [ ] 모바일과 PC 실제 페이지에서 크롭, 중복, 깨짐, 로딩을 확인했다.

## 13. 생성 프롬프트 기본 블록

```text
Create one editorial visual for the specified content role.
Choose a dynamic palette from the topic or source photograph: one primary color,
one accent color, and neutrals. Do not default to navy/green/ivory.
Use 85–92% of a 1200×675 canvas with only 3–5% outer safe margin.
No decorative left vertical color stripe. No gray card backdrop.
No repeated rounded-card template. No tiny text.
Prefer a rights-cleared real photograph; if unavailable, create a high-quality
photorealistic or editorial visual without implying documentary evidence.
For factual Korean or English text, generate a text-free background and add
verified text with a deterministic renderer. Keep the visual readable at 360px.
```

- 스타일 취향보다 실제 모바일 가독성, 사실 정확성, 권리 상태를 우선한다.
