# kFarmAI 공공정보 교차확인 설계

## 1. public-data.html 역할

`public-data.html`은 AI 참고 진단 결과를 그대로 믿게 하는 화면이 아니라, 사용자가 작물명·증상·지역·재배유형을 기준으로 공식정보를 함께 확인하도록 돕는 교차 확인 화면이다.

기본 흐름은 다음과 같다.

```text
AI 참고 진단 결과
→ 작물명·증상·지역·재배유형 확인
→ 공공정보 확인 우선순위 표시
→ NCPMS / 농약안전정보 / 농업날씨 / 재배가이드 / 지역정보 연결
→ 정보가 부족하면 지역 농업기관 또는 공식 상담창구 확인 안내
```

## 2. MVP 매칭 케이스

현재 서비스 가능한 전용 매칭 사례는 4개다.

| 작물 | 증상 | 목적 |
|---|---|---|
| 고추 | 잎말림 | 병해충 정보, 안전사용기준, 농업날씨, 지역기관 확인 |
| 토마토 | 반점 | 병해충 정보, 안전사용기준, 농업날씨 확인 |
| 딸기 | 잿빛곰팡이 | 병해 정보, 습도·환기 조건, 안전사용기준 확인 |
| 벼 | 도열병 | 병해 정보, 기상조건, 재배가이드, 지역기관 확인 |

전용 매칭 사례가 없는 경우에는 기본 공공정보 확인 카드로 fallback한다.

## 4. 매칭 방식

`findPublicDataMatch({ crop, symptom })`는 아래 순서로 전용 사례를 찾는다.

1. 작물명과 증상 정확 매칭
2. aliases 포함 매칭
3. 작물명 포함 + 증상 포함 매칭
4. 증상 키워드만 매칭
5. 매칭 실패 시 fallback

입력값은 공백 제거 후 비교한다. URL query, localStorage, 직접 입력을 모두 지원한다.

지원 query:

- `crop`
- `symptom`
- `region`
- `type`
- `cultivationType`

확인하는 localStorage key:

- `kfarmai:lastDiagnosis`
- `kfarmai:lastAiDiagnosis`

localStorage 값이 깨져 있어도 페이지가 깨지지 않도록 무시한다.

## 5. 기관정보 처리 원칙

- 공식 URL이 확인된 기관만 링크로 표시한다.
- 전화번호와 담당자명은 공식 출처가 확인된 경우만 표시한다.
- 확인되지 않은 연락처, 담당자명, 기관 정보를 생성하지 않는다.
- 현재 지역별 상세 기관 DB가 없으면 공식 홈페이지에서 지역 기관 정보를 확인하도록 안내한다.

## 6. 표현 안전 원칙

사용자 화면에서는 다음 성격의 표현을 우선한다.

- AI 참고 진단
- 원인 후보
- 확인 후보
- 공공정보로 교차 확인
- 공식정보 확인
- 제품 라벨 확인
- 참고자료
- 전문가 상담 권장

다음 성격의 표현은 사용하지 않는다.

- 단정형 진단 표현
- 처방 확정처럼 보이는 표현
- 특정 농약 사용 유도
- 방제 실행 시점을 지시하는 표현
- 구매, 가격 비교, 결제 유도 표현

## 7. 향후 자동연동 방향

1. NCPMS와 농약안전정보시스템의 공식 검색 가능 방식 확인
2. 작물명·증상 키워드와 공식자료 검색어 매핑 테이블 분리
3. 지역 농업기술센터/농업기술원 링크 DB 구축
4. AI 참고 진단 결과의 crop/symptom 추출값을 안정적으로 query 전달
5. 매칭 사례를 `data/public-data-match-cases.json`으로 분리
6. 관리자 검수 후 공식 링크와 키워드 active 전환

## 8. 구현 전 체크리스트

- 외부 공식 링크가 실제 접속 가능한지 확인
- 내부 링크 파일이 존재하는지 확인
- 금지 표현이 사용자 화면에 없는지 확인
- 가짜 전화번호/담당자 정보가 없는지 확인
- 없는 매칭 사례에서는 fallback 카드가 보이는지 확인
- 모바일에서 직접 입력과 예시 칩이 자연스럽게 동작하는지 확인
