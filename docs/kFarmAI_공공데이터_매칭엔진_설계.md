# kFarmAI 공공데이터 매칭엔진 설계

## 1. 매칭엔진의 목적

매칭엔진은 AI 참고 진단 결과를 공공데이터 출처와 연결하는 중간 로직이다. AI가 정리한 작물, 증상, 원인 후보를 그대로 확정하지 않고, 공공데이터에서 어떤 항목을 함께 확인할 수 있는지 정리한다.

매칭엔진의 역할:

- AI가 추정한 작물, 증상, 원인 후보를 구조화한다.
- 공공데이터 출처별로 확인 가능한 항목을 찾는다.
- NCPMS, 농약안전정보시스템, 농업날씨, 농사로, 재배가이드와 연결한다.
- 사용자가 이해하기 쉬운 매칭 결과를 만든다.
- 1장 보고서 생성에 필요한 데이터를 반환한다.

중요 문장:

> 매칭엔진은 AI 진단을 확정하는 기능이 아니라, AI 원인 후보와 공공데이터 출처의 확인 항목을 연결하는 기능이다.

금지 표현:

- AI 진단이 맞습니다
- 확정 진단
- 최종 처방
- 이 병입니다
- 이 농약을 쓰세요
- 추천 농약
- 오늘 방제하세요

허용 표현:

- 공공데이터 관련 항목 매칭됨
- 출처 기준 확인 항목 있음
- 관련 공공데이터 출처와 연결됨
- 추가 검증은 관계기관 확인 권장

## 2. 전체 연결 흐름

```text
사용자 사진/문자 입력
↓
AI 참고 진단 결과 생성
↓
AI 결과 구조화
↓
매칭엔진 입력
↓
작물명 표준화
↓
증상 키워드 표준화
↓
원인 후보 category 분류
↓
공공데이터 출처별 매칭
↓
매칭 결과 생성
↓
1장 보고서 생성
↓
마이페이지 저장
```

이 흐름에서 매칭엔진은 AI 참고 진단 결과와 공공데이터 확인 화면 사이에 위치한다. 사용자에게는 복잡한 점수나 내부 규칙을 보여주지 않고, "무엇을 어떤 출처에서 확인할 수 있는지"만 쉬운 문장으로 제공한다.

## 3. 매칭엔진 입력 데이터

매칭엔진은 아래 형태의 AI 진단 결과를 입력받는다.

```json
{
  "diagnosisId": "local-001",
  "crop": "고추",
  "cropCandidates": ["고추", "청양고추"],
  "symptom": "잎말림",
  "symptomKeywords": ["잎말림", "잎 오그라듦", "신엽 말림"],
  "region": "충청권",
  "cultivationType": "노지",
  "growthStage": "생육기",
  "aiSummary": "잎이 말리는 증상은 해충, 바이러스성 증상, 환경 스트레스가 함께 원인이 될 수 있습니다.",
  "aiCandidates": [
    {
      "name": "해충 피해 가능성",
      "category": "pest",
      "keywords": ["진딧물", "총채벌레", "흡즙해충", "해충"]
    },
    {
      "name": "바이러스성 증상 가능성",
      "category": "disease",
      "keywords": ["바이러스", "모자이크", "위조"]
    },
    {
      "name": "고온·건조 스트레스 가능성",
      "category": "environment",
      "keywords": ["고온", "건조", "수분부족"]
    }
  ],
  "confidenceLevel": "reference"
}
```

필수 입력:

- `crop`: 대표 작물명
- `symptom`: 대표 증상명
- `aiCandidates`: AI가 정리한 원인 후보 목록

선택 입력:

- `region`: 지역 또는 권역
- `cultivationType`: 노지, 시설재배, 실내재배 등
- `growthStage`: 생육기, 개화기, 수확기 등
- `imageUrl`: 진단에 사용한 이미지 URL 또는 저장 경로

입력 데이터는 AI 결과 원문이 아니라 매칭 가능한 구조화 데이터여야 한다. 자연어만 있으면 공공데이터 출처와 안정적으로 연결하기 어렵다.

## 4. 매칭엔진 출력 데이터

매칭엔진은 1장 보고서를 만들 수 있도록 아래 형태를 반환한다.

```json
{
  "reportType": "public_data_matching",
  "crop": "고추",
  "symptom": "잎말림",
  "matchStatus": "공공데이터 관련 항목 매칭됨",
  "mainSummary": "AI 후보 중 해충·바이러스·환경 스트레스 항목은 공공데이터 출처와 함께 확인할 수 있습니다.",
  "matchedSources": [
    {
      "sourceKey": "ncpms",
      "sourceName": "NCPMS 국가농작물병해충관리시스템",
      "checkedPoint": "병해충·발생환경 확인",
      "matchedKeywords": ["고추", "잎말림", "해충", "바이러스"],
      "resultText": "AI 후보 중 병해충·해충 관련 항목은 NCPMS 병해충 정보와 연결됩니다.",
      "sourceUrl": "https://ncpms.rda.go.kr/"
    },
    {
      "sourceKey": "psis",
      "sourceName": "농약안전정보시스템",
      "checkedPoint": "등록작물·대상 병해충·안전사용기준·등록취소 여부 확인",
      "matchedKeywords": ["고추", "해충"],
      "resultText": "농약 사용 판단은 AI 결과가 아니라 공식 안전사용기준과 제품 라벨 확인이 필요합니다.",
      "sourceUrl": "https://psis.rda.go.kr/"
    },
    {
      "sourceKey": "agriWeather",
      "sourceName": "농업날씨",
      "checkedPoint": "기온·강수·습도·고온·건조 확인",
      "matchedKeywords": ["고온", "건조"],
      "resultText": "환경 스트레스 후보는 최근 날씨 조건과 함께 확인할 수 있습니다.",
      "sourceUrl": "agri-weather.html"
    }
  ],
  "nextStep": "증상이 계속되거나 피해가 확산되면 사진과 발생환경을 가지고 관계기관 확인을 권장합니다.",
  "caution": "이 결과는 참고자료입니다. 최종 판단은 공식자료와 전문가 확인이 필요합니다."
}
```

출력 데이터는 화면 표시와 저장을 모두 고려한다. `matchedSources`는 보고서 본문에 표시되고, `matchStatus`, `mainSummary`, `nextStep`, `caution`은 1장 보고서의 핵심 문구가 된다.

## 6. category별 매칭 규칙

AI 후보 category에 따라 기본 매칭 대상을 정한다.

| category | 기본 매칭 대상 |
|---|---|
| pest | ncpms, psis, cropGuide, localAgency |
| disease | ncpms, psis, cropGuide, localAgency |
| environment | agriWeather, cropGuide, nongsaro |
| nutrition | cropGuide, nongsaro, localAgency |
| water | agriWeather, cropGuide, nongsaro |
| management | cropGuide, nongsaro |
| unknown | ncpms, cropGuide, localAgency |

주의:

> category는 확정 원인이 아니라 매칭 방향을 정하기 위한 분류다.

예를 들어 `pest`는 해충이라고 확정하는 의미가 아니라, NCPMS 병해충 정보와 PSIS 안전사용기준을 함께 확인해야 할 수 있다는 뜻이다.

## 7. 작물명 표준화 규칙

사용자 입력과 AI 결과의 표현이 달라도 내부 대표 작물명으로 통일한다.

### 고추

- 고추
- 청양고추
- 풋고추
- 홍고추
- pepper

대표값: `고추`

### 토마토

- 토마토
- 방울토마토
- tomato

대표값: `토마토`

### 딸기

- 딸기
- strawberry

대표값: `딸기`

### 벼

- 벼
- 쌀
- 논벼
- rice

대표값: `벼`

표준화는 공공데이터 검색어와 보고서 제목을 안정적으로 만들기 위한 전처리다. 사용자가 입력한 원문은 별도로 보존할 수 있지만, 매칭에는 대표값을 우선 사용한다.

## 9. 매칭 점수 설계

단순 MVP 점수:

| 기준 | 점수 |
|---|---:|
| 작물명 일치 | +40 |
| 증상 키워드 일치 | +30 |
| AI 후보 category 일치 | +20 |
| 원인 후보 키워드 일치 | +10 |

총점 기준:

| 총점 | 상태 문구 |
|---:|---|
| 70점 이상 | 공공데이터 관련 항목 매칭됨 |
| 40~69점 | 공공데이터 기준 확인 항목 있음 |
| 40점 미만 | 일반 확인 항목 안내 |

주의:

- 점수는 사용자에게 직접 노출하지 않는다.
- 보고서에는 쉬운 상태 문구만 표시한다.
- 점수는 공공데이터 연결 우선순위를 정하는 내부 기준이다.

## 11. fallback 매칭

대표 케이스에 없을 때는 기본 보고서를 생성한다.

상태:

```text
일반 확인 항목 안내
```

문구:

```text
입력한 작물·증상에 대한 전용 매칭 사례는 아직 준비 중입니다.
다만 공공데이터 출처 기준으로 아래 항목을 확인할 수 있습니다.
```

기본 출처:

- NCPMS: 병해충·발생환경
- 농약안전정보: 등록작물·안전사용기준
- 농업날씨: 기온·강수·습도
- 재배가이드: 관리포인트
- 관계기관: 사진·발생환경 확인

fallback에서도 AI 결과를 확정하거나 특정 처방처럼 표현하지 않는다. 데이터가 부족할수록 "추가 검증 권장"과 "관계기관 확인 권장"을 강조한다.

## 12. 1장 보고서 변환 규칙

매칭엔진 결과는 1장 보고서로 변환된다.

보고서 구성:

- 제목: 공공데이터 매칭 보고서
- 작물·증상
- AI 후보 chip
- 매칭 결과 1문장
- 출처별 확인한 점 3~5줄
- 추가 검증 안내
- 주의문구

디자인 원칙:

- 연구논문처럼 길지 않게
- 큰 글씨
- 쉬운 문장
- 핵심만
- 모바일 카드형
- 마이페이지 저장 가능

보고서 문구 예시:

```text
공공데이터 매칭 보고서

고추 · 잎말림

AI 참고 진단 후보
[해충 피해 가능성] [바이러스성 증상 가능성] [고온·건조 스트레스]

매칭 결과
AI 후보 중 해충·바이러스·환경 스트레스 항목은 공공데이터 출처와 함께 확인할 수 있습니다.

출처별 확인한 점

- 농업날씨: 고온·건조·강수 확인

주의
이 보고서는 참고자료입니다. 최종 판단은 공식자료와 전문가 확인이 필요합니다.
```

## 13. PSIS 인증키와 연결 계획

사용자가 신청한 PSIS API:

- 농약등록정보
- 등록취소 농약정보
- 시험연구기관 지정현황
- 농약공정분석법

매칭엔진 v1에서 우선 사용하는 항목:

1. 농약등록정보
2. 등록취소 농약정보

후순위:

3. 시험연구기관 지정현황
4. 농약공정분석법

PSIS 보고서 문구:

```text
농약안전정보시스템 기준으로 등록작물, 대상 병해충, 안전사용기준, 등록취소 여부를 확인할 수 있습니다.
농약 사용 여부는 AI 결과가 아니라 제품 라벨과 공식 안전사용기준을 기준으로 확인해야 합니다.
```

주의:

- 인증키는 `.env.local` 또는 서버 환경변수에만 둔다.
- 프론트 JS/HTML에 직접 노출하지 않는다.
- GitHub에 커밋하지 않는다.
- PSIS API 연동은 서버 또는 edge function에서 처리한다.
- 브라우저에서 인증키를 직접 호출하는 구조는 사용하지 않는다.
