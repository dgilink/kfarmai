# V3 커뮤니티 운영·사진 계약

## 관리자와 신고

- 관리자 권한은 `community_user_roles`의 `moderator` 역할만 신뢰한다. 브라우저 저장값, 이메일 문자열, 사용자 수정 가능 metadata는 권한 근거가 아니다.
- 역할 부여·회수는 신뢰된 DB 운영 절차에서만 수행한다. 브라우저 역할 쓰기 권한은 없다.
- 신고자는 자기 신고만 조회할 수 있고, moderator만 전체 queue 조회와 상태 변경이 가능하다.
- 상태는 `pending`, `reviewed`, `dismissed`, `actioned`다. 상태 변경은 검토 기록이며 게시글·댓글을 자동 삭제하지 않는다.
- queue RPC는 최대 100건의 대상 미리보기를 한 번에 반환해 대상별 추가 조회를 만들지 않는다.

## AI 질문 초안과 사진

- AI 참고 확인 결과는 `source=ai_diagnosis`인 편집 가능한 초안으로만 전달한다. 자동 공개하지 않는다.
- 진단 사진은 질문 전환 시 브라우저 IndexedDB에 최대 24시간 로컬 보관한다. 게시 확정 전 Storage 업로드는 없다.
- 사용자가 취소하면 로컬 초안 사진을 즉시 제거한다. 중단된 탭의 만료 초안은 다음 접근 때 정리한다.
- 게시 확정 시 기존 `post-images` 업로드 흐름을 사용한다. DB insert 실패 시 이번 요청에서 올린 Storage 객체를 회수해 orphan 파일을 남기지 않는다.
- 모든 새 게시 사진은 canvas로 다시 인코딩해 EXIF/GPS/촬영기기 metadata와 원본 파일명을 제거한다. JPEG/PNG/WebP만 허용하며 해석할 수 없는 이미지는 원본 그대로 업로드하지 않는다.
- 게시글 삭제가 성공하면 연결된 `post-images` 객체도 제거를 시도한다. Storage 제거 장애는 별도 운영 점검 대상으로 기록한다.

## MY와 성능

- MY는 내가 쓴 글, 저장한 글, 차단한 사용자, 계정 설정을 제공한다.
- 저장한 글은 북마크 1회 + 게시글 batch 1회로 읽으며 게시글별 요청을 만들지 않는다.
- 신고 관리 링크는 서버/DB 역할 확인이 성공한 moderator에게만 보인다. URL 보안은 DB RLS/RPC가 담당한다.
