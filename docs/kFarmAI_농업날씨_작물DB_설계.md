# kFarmAI 농업날씨·작물DB 설계

## 1. 기능 목적

kFarmAI 농업날씨는 단순 기상 정보 표시가 아니라, 사용자가 농작업 전 확인해야 할 항목을 정리하는 참고 도구이다.

핵심 흐름은 다음과 같다.

```text
기상 항목 확인
→ 재배유형별 체크포인트
→ 작물별 체크포인트
→ AI 참고 진단 / NCPMS 병해충 정보 / 재배가이드 / 관련 질문 보기
```

날씨 정보는 참고자료이며 실제 작업 여부는 현장 상황과 공식 정보를 함께 확인해야 한다.

## 2. 단순 날씨 서비스와의 차이

일반 날씨 서비스는 기온, 강수, 습도, 풍속 같은 수치를 중심으로 제공한다. kFarmAI 농업날씨는 같은 수치를 농작업 참고 맥락으로 재정리한다.

- 기온: 고온·저온에 따른 잎 말림, 시듦, 생육 저하 확인
- 강수: 배수 상태, 과습, 작업 전후 주의 확인
- 습도: 결로, 환기, 곰팡이성 증상 확인
- 풍속: 살포 작업 전후 주의, 시설물 상태 확인
- 일교차: 시설 내부 결로와 야간 저온 확인

단, 병해충 발생을 예측하거나 작업 시점을 단정하지 않는다.

## 3. 내부 요약 우선 원칙

외부 공식 사이트는 보조 확인 경로로 둔다. 화면에서는 kFarmAI 내부 요약과 체크포인트를 먼저 보여준다.

- 내부 우선: 기상 항목 카드, 농작업 참고 카드, 재배유형 체크포인트, 작물별 체크포인트
- 보조 확인: 농업날씨365 공식 서비스, 기상청 등 공식 제공처

농업날씨365 안내 문구:

```text
농업날씨365는 농업기상 정보를 확인할 수 있는 공식 서비스입니다. kFarmAI의 농업날씨 요약은 참고자료이며, 자세한 관측 정보는 공식 서비스를 함께 확인하세요.
```

## 4. 권역 선택 구조

권역은 한 번에 전체 지역을 펼치지 않고, 권역 선택 후 해당 권역의 지역만 보여주는 구조로 한다.

권역 순서:

```text
서울 / 경기 / 강원 / 충북 / 충남 / 전북 / 전남 / 경북 / 경남 / 제주
```

서울을 포함하는 이유:

kFarmAI는 전문 농업인뿐 아니라 도시농업, 홈가드닝, 베란다 식물, 텃밭 사용자도 함께 사용하는 서비스이므로 서울을 제외하지 않는다.

## 5. 지역 선택 구조

권역별 대표 지역은 다음 기준으로 확장한다.

- 도시농업·홈가드닝 진입 지역: 서울
- 농업 비중이 높은 시군: 순천, 나주, 안동, 홍성 등
- 시설재배·스마트팜 참고 지역: 논산, 부여, 밀양, 진주 등
- 도서·해안성 기상 차이가 큰 지역: 제주, 서귀포, 해남 등

지역 데이터는 기상 API 연동 전에도 빈 화면이 나오지 않도록 기본 참고값 또는 `확인 필요`로 표시한다.

## 6. 재배유형 순서

재배유형은 홈가드닝 사용자에서 전문 농업·시설재배·스마트팜 사용자로 자연스럽게 확장되도록 다음 순서를 유지한다.

```text
베란다·실내 / 텃밭 / 노지 / 시설재배 / 스마트팜
```

## 7. 작물 카테고리 순서

작물 카테고리는 다음 순서를 유지한다.

```text
전체 / 홈가드닝 / 텃밭·채소 / 과채류 / 과수 / 벼·곡류 / 시설·스마트팜 / 특용·화훼
```

전체 다음에 홈가드닝을 배치하는 이유:

식집사, 베란다 식물, 홈가드닝, 도시농업 사용자가 쉽게 진입해야 하기 때문이다.

## 8. 작물·식물 확장 리스트

초기 DB는 아래 범위를 우선 반영한다.

- 홈가드닝: 몬스테라, 바질, 다육식물, 산세베리아, 로즈마리 등
- 텃밭·채소: 상추, 배추, 마늘, 양파, 감자 등
- 과채류: 고추, 토마토, 방울토마토, 오이, 딸기, 수박 등
- 과수: 사과, 배, 포도 등
- 벼·곡류: 벼, 옥수수, 콩 등
- 시설·스마트팜: 딸기 육묘기, 딸기 본포 재배기, 파프리카 등
- 특용·화훼: 표고버섯, 수국, 장미 등

향후에는 품목명을 늘리되, 정확한 공공 코드가 확인되지 않은 값은 코드로 저장하지 않고 검색 후보 키워드로 관리한다.

## 9. 딸기 육묘기 / 딸기 본포 재배기 분리 기준

딸기는 생육 단계에 따라 확인 포인트가 다르므로 분리한다.

- 딸기 육묘기: 육묘장 배수, 포트 과습, 고온다습, 잎 병반 확인
- 딸기 본포 재배기: 야간 저온, 결로, 꽃과 과실 주변 곰팡이성 증상, 하우스 환기 확인

이 분리는 병명을 확정하기 위한 것이 아니라, 날씨 조건에 따라 우선 확인할 항목을 다르게 보여주기 위한 것이다.

## 10. 수국·화훼류·시설재배 작물 추가 기준

화훼류는 일반 노지 작물과 달리 꽃, 잎, 시설 내부 환경이 중요하다.

추가 기준:

- 습도와 결로에 민감한 작물
- 시설 내부 환기·제습 관리가 중요한 작물
- 홈가드닝과 전문 시설재배 양쪽에서 쓰이는 작물
- 사용자가 증상을 사진이나 문장으로 자주 질문할 수 있는 작물

수국은 습도, 결로, 꽃 주변 곰팡이성 증상 확인이 중요하므로 특용·화훼 카테고리에 포함한다.

## 11. 작물별 날씨 체크포인트 작성 원칙

작물별 체크포인트는 위험 예측이 아니라 확인 항목으로 작성한다.

사용 원칙:

- “확인하세요”
- “함께 확인하세요”
- “참고할 수 있습니다”
- “필요할 수 있습니다”
- “현장 상황과 공식 정보를 함께 확인하세요”

예:

```text
고온·건조가 이어지면 잎 말림, 시듦, 생육 저하를 확인하세요.
강우 후에는 열매 반점, 줄기 밑부분 시듦, 배수 상태를 함께 확인하세요.
```

## 12. 재배유형별 체크포인트 작성 원칙

재배유형별 문구는 작업 지시가 아니라 확인 항목 중심으로 작성한다.

- 베란다·실내: 실내 온도, 창가 일조, 환기, 흙 마름 속도
- 텃밭: 비 온 뒤 배수, 흙 마름, 잎 병반, 작은 면적의 과습·건조
- 노지: 강수, 풍속, 고온·저온 영향
- 시설재배: 시설 내부 온습도, 결로, 환기
- 스마트팜: 외부 기상과 내부 센서값의 병행 확인

## 13. 초성 검색 설계

작물 수가 늘어나므로 초성 검색을 지원한다.

예:

```text
ㄱㅊ → 고추
ㅌㅁㅌ → 토마토
ㄸㄱ → 딸기
ㄸㄱㅇㅁ → 딸기 육묘기
ㄸㄱㅂㅍ → 딸기 본포 재배기
ㅁㅅㅌㄹ → 몬스테라
ㅅㄱ → 수국 / 사과 / 상추 후보
ㅂㅊ → 배추
ㅇㅍ → 양파
ㅁㄴ → 마늘
```

1차 구현은 `chosung` 배열과 작물명 자동 초성 변환을 함께 사용한다. 검색 결과는 작물 칩 목록을 필터링하는 방식으로 보여준다.

## 17. 기상청 단기예보 Worker 확장 후보

현재 Cloudflare Worker는 KAMIS/NCPMS를 중계한다. 기상청 단기예보도 같은 방식으로 확장할 수 있다.

후보 엔드포인트:

```text
GET /api/weather/forecast?region=순천
```

응답 구조 후보:

```json
{
  "source": "KMA",
  "region": "순천",
  "items": {
    "temperature": "",
    "minTemp": "",
    "maxTemp": "",
    "rainProbability": "",
    "rainAmount": "",
    "humidity": "",
    "windSpeed": "",
    "sky": "",
    "dailyTempRange": ""
  },
  "fallback": false,
  "notice": "농작업 참고자료입니다."
}
```

API 실패 시에는 `data/agri_weather.json` 또는 기본 참고 데이터로 fallback한다.

Fallback 문구:

```text
현재 날씨 정보를 불러오지 못했습니다. 기본 참고 정보와 공식 기상 정보를 함께 확인해주세요.
```

## 18. 향후 구현 단계

1. 현재 정적 JSON 기반 체크포인트 UI 안정화
2. 작물 프로필 확장
3. 지역별 위경도 또는 기상청 격자 좌표 매핑 파일 추가
4. Cloudflare Worker에 `/api/weather/forecast` 엔드포인트 추가
5. Worker secret으로 기상청 API 키 관리
6. 프론트는 Worker URL만 호출
7. API 실패 시 `data/agri_weather.json` fallback 유지
8. 사용자 질문, NCPMS, 재배가이드와 연결 강화

API 키, secret, `.env.local` 값은 문서와 프론트엔드 코드에 절대 기록하지 않는다.

## 19. 2026-07-04 보강 반영 사항

이번 보강에서는 작물 DB를 초기 23개 수준에서 홈가드닝, 텃밭·채소, 과채류, 과수, 벼·곡류, 시설·스마트팜, 특용·화훼 전체 확장 리스트로 넓혔다. 같은 작물이 여러 진입 경로에 걸치는 경우 중복 프로필을 만들지 않고 `categories` 배열로 대응한다. 예를 들어 토마토는 과채류와 시설·스마트팜에서 함께 찾을 수 있고, 장미는 홈가드닝과 특용·화훼에서 함께 찾을 수 있다.

### 작물 DB 구조 원칙

- `primaryCategory`는 대표 분류를 나타낸다.
- `categories`는 전체, 홈가드닝, 텃밭·채소, 과채류, 과수, 벼·곡류, 시설·스마트팜, 특용·화훼 중 복수 선택을 허용한다.
- 정확한 공공 코드가 확인되지 않은 항목에는 임의 `ncpms_code`를 넣지 않는다.
- NCPMS 연결은 `ncpmsQueries`에 작물명과 증상 키워드 후보를 넣어 검색 기반으로 연결한다.
- 작물별 날씨 포인트는 위험 예측이 아니라 우선 확인할 증상과 관리 항목으로 작성한다.

### 전국 권역·지역 선택 구조

권역 순서는 다음 순서를 유지한다.

```text
서울 / 인천 / 경기 / 강원 / 대전·세종 / 충북 / 충남 / 광주 / 전북 / 전남 / 대구 / 경북 / 부산·울산 / 경남 / 제주
```

서울 권역은 도시농업, 홈가드닝, 베란다 식물 사용자를 포함하기 위해 유지한다. 지역 데이터는 `data/weather-regions.json`으로 분리하고, 실제 기상청 API 연동 전까지 지역명만 제공한다.

### 기상청 단기예보 격자좌표 원칙

기상청 단기예보 API는 지역명을 직접 조회하는 구조가 아니라 지역을 예보 격자좌표 `nx`, `ny`로 변환해 조회하는 구조다. 이 격자좌표는 필지·건물 단위의 핀셋 날씨가 아니라 5km 내외 예보 격자 기반 참고자료로 다룬다.

kFarmAI에서는 임의 좌표를 만들지 않는다. `nx`, `ny`는 공식 기상청 격자 좌표표 또는 검증된 변환식으로만 채운다. 아직 검증되지 않은 지역은 `nx`, `ny`를 `null`로 두고 `좌표 확인 필요` 상태로 관리한다. 좌표 검수 전에는 `data/agri_weather.json` 기반 기본 참고 정보와 공식 기상 정보 확인 경로를 함께 제공한다.

### 재배유형·작물 카테고리 순서

재배유형 순서는 다음을 유지한다.

```text
베란다·실내 / 텃밭 / 노지 / 시설재배 / 스마트팜
```

작물 카테고리 순서는 다음을 유지한다.

```text
전체 / 홈가드닝 / 텃밭·채소 / 과채류 / 과수 / 벼·곡류 / 시설·스마트팜 / 특용·화훼
```

전체 다음에 홈가드닝을 배치해 식집사, 베란다 식물, 도시농업 사용자가 바로 진입할 수 있게 한다.

### 단계 분리와 시설 화훼 포함 기준

딸기는 일반 딸기, 딸기 육묘기, 딸기 본포 재배기를 분리한다. 육묘기는 포트 과습, 육묘장 배수, 잎 병반 확인이 중요하고, 본포 재배기는 야간 저온, 결로, 꽃과 과실 주변 증상 확인이 중요하기 때문이다.

수국, 장미, 국화 같은 화훼류는 홈가드닝과 시설재배 양쪽에서 자주 확인되는 작물이다. 특히 습도, 결로, 환기, 꽃과 잎 주변 증상 확인이 중요하므로 특용·화훼와 홈가드닝 진입 경로에 포함한다.
